# 스팀 출시 + 창작마당 가이드

이 문서는 러버덕 디버거를 스팀에 올리고 창작마당(Workshop)을 여는 전 과정을 순서대로 정리한 것이다.
**내가 대신 못 하는 일**(계정 생성·결제·세금 서류·심사 제출)과 **코드로 준비할 수 있는 일**을 명확히 갈라 뒀다.

---

## 0. 먼저 알아야 할 것

| 항목 | 내용 |
|---|---|
| 비용 | **앱당 $100** (Steam Direct 수수료). 환불은 안 되지만 **누적 매출 $1,000을 넘기면 되돌려준다** |
| 수수료 | 매출의 30% (Valve 몫). 매출 구간이 커지면 25% → 20%로 내려감 |
| 소요 기간 | 계정 등록 후 **30일 대기**가 강제된다. 그 뒤 빌드 심사 **1~5일** |
| 심사 | 실행되는지, 스토어 페이지가 규정에 맞는지 본다. 게임성 심사는 아니다 |
| 카테고리 | 게임이 아니라 **Software → Utilities**로 낸다 (Wallpaper Engine·Bongo Cat과 같은 갈래) |

**30일 대기가 핵심이다.** 오늘 결제해도 30일 뒤에야 출시가 가능하니, 출시일을 잡았다면 **한 달 전에 결제부터** 해야 한다.

## 1. 사용자가 직접 해야 하는 일 (내가 대행 불가)

### 1-1. Steamworks 파트너 등록
1. https://partner.steamgames.com 에서 가입
2. **본인 확인**: 신분증, 주소, 전화번호
3. **세금 서류(W-8BEN)**: 한국 거주자는 조세조약으로 원천징수 10%. 안 내면 30% 떼인다
4. **은행 계좌**: 매출 정산용 (해외 송금 가능한 계좌)

> 개인 사업자로 내도 되고 개인 명의도 된다. 다만 세금 신고는 본인 책임이다.

### 1-2. $100 결제 → AppID 발급
- 결제하면 **AppID**(예: `3712345`)가 나온다. **이 숫자가 있어야 창작마당 코드가 실제로 동작한다.**
- 발급되면 나한테 알려주면 된다. 그 숫자만 있으면 연동을 끝낼 수 있다.

### 1-3. 스토어 페이지 준비물
직접 만들어야 하는 자료다. (내가 초안은 써줄 수 있다)

| 자료 | 규격 | 비고 |
|---|---|---|
| 헤더 이미지 | 460×215 | 스토어 목록에 뜨는 대표 이미지 |
| 캡슐 이미지 | 231×87, 616×353, 374×448 | 위치별로 여러 장 필요 |
| 라이브러리 이미지 | 600×900 | 사용자 라이브러리용 세로 이미지 |
| 스크린샷 | 1920×1080, **최소 5장** | 이미 만든 `assets/shot-*.png` 를 확장하면 된다 |
| 트레일러 | 영상 | 필수는 아니지만 있으면 전환율이 크게 오른다 |
| 설명문 | 짧은 설명 + 긴 설명 | README 영문판을 다듬어 쓰면 된다 |

### 1-4. 창작마당 활성화
파트너 사이트에서 앱 설정 → **Workshop** 항목을 켜야 한다. 켜는 순간 스토어 페이지에 창작마당 탭이 생긴다.
- 항목 유형: **아이템(Items)** 으로 설정
- 검수 방식: **자유 업로드**(누구나 올림) vs **큐레이션**(승인한 것만 노출)
  → "유저들이 자유롭게" 원하니 **자유 업로드**로 설정

## 2. 코드/빌드 쪽 (내가 하는 일)

### 2-1. 스팀 빌드 형태
스팀은 우리 NSIS 설치파일을 쓰지 않는다. **압축 해제된 앱 폴더**를 통째로 받아 자체 배포한다.
- `npm run dist` 가 만드는 `dist/win-unpacked/` 가 그대로 스팀 빌드 내용물이 된다
- 업로드는 **SteamPipe**(`steamcmd`) 로 한다. 설정 파일(app_build.vdf)은 AppID가 나오면 만든다

### 2-2. 창작마당 연동 구조
`steamworks.js` 를 **메인 프로세스에서만** 쓴다. 이게 중요한 이유:

> steamworks.js 문서는 Electron에서 `contextIsolation: false`, `nodeIntegration: true` 로 바꾸라고 안내한다.
> 그건 **렌더러에서 직접 부를 때** 이야기다. 우리는 스킨·파일·설정을 전부 메인에서 처리하고
> 렌더러는 preload 화이트리스트로만 통신하므로, **렌더러 보안 설정을 건드리지 않고** 붙일 수 있다.
> 남이 만든 스킨팩을 여는 앱에서 이 방어선을 무너뜨리는 건 말이 안 된다.

동작 흐름:

```
[구독]  사용자가 스팀 창작마당에서 Subscribe
          → 스팀이 알아서 다운로드
          → 앱 시작 시 getSubscribedItems() + installInfo() 로 폴더 경로를 얻어
            기존 스킨 검증기(src/skins.js)에 그대로 통과시켜 목록에 합침

[게시]  설정 → 스킨 → "창작마당에 올리기"
          → createItem() 으로 빈 아이템 생성
          → updateItem() 으로 스킨 폴더 + 미리보기 이미지 + 제목/설명/태그 업로드
          → 첫 게시 때는 스팀 약관 동의 페이지가 뜬다(Valve 요구사항)
```

**중요**: 창작마당에서 받은 스킨도 **로컬 스킨과 똑같이 검증**한다. 스팀에서 왔다고 신뢰하지 않는다.
(zip slip·실행파일·용량 폭탄·매니페스트 위조 검사 그대로 적용)

### 2-3. 지금 상태 (2026-08-02 기준)

코드는 들어가 있다. `src/steam.js` + 설정창 연동까지 완료.

| 항목 | 상태 |
|---|---|
| 스팀 없을 때 앱 동작 | ✅ 검증 완료 — 기존과 100% 동일 (스모크 테스트 결과 일치) |
| 스팀 연결 | ✅ 검증 완료 — 테스트 AppID(480)로 앱에서 `available: true` 확인 |
| 구독 아이템 → 스킨 목록 | ✅ 코드 완료 / ⏳ 실제 아이템으로는 미검증 (AppID 필요) |
| 창작마당 업로드 | ✅ 코드 완료 / ⏳ **미검증** — 테스트용 공용 워크샵(Spacewar)에 쓰레기 아이템을 올리지 않으려고 일부러 안 돌렸다 |

- AppID를 받으면 프로젝트 루트에 `steam_appid.txt` 파일을 만들고 그 숫자만 넣으면 바로 테스트가 된다
  (이 파일은 **개발용**이다. `.gitignore`에 넣어뒀고, 스팀으로 배포된 빌드에는 넣지 않는다 — 클라이언트가 알려준다)
- 설정창 스킨 카드에 **↑ 버튼**(창작마당 업로드)이 뜨고, 구독한 스킨은 **≡ 표시**로 구분된다
  (구독 해제는 앱이 아니라 스팀에서 한다)

## 3. 순서대로 할 일

```
[오늘]      1. Steamworks 가입 + 본인확인 + 세금서류        ← 사용자
            2. $100 결제 → AppID 발급                        ← 사용자
                 ↓ (30일 대기 시작)
[대기 중]   3. 창작마당 연동 완성 + AppID로 실제 테스트      ← 나 (AppID 필요)
            4. 스토어 이미지·설명문 준비                     ← 사용자(자료) + 나(초안)
            5. SteamPipe 빌드 업로드 설정                    ← 나
            6. 파트너 사이트에서 창작마당 켜기               ← 사용자
[30일 후]   7. 빌드 심사 제출 → 1~5일                        ← 사용자
            8. 출시일 지정 → 공개                            ← 사용자
```

## 4. 결정해야 할 것

### 가격
GitHub에 MIT로 공개돼 있고 exe도 무료로 받을 수 있다. 그래도 스팀 유료 판매는 흔하고 합법이다
(스팀 사용자는 "설치·업데이트·창작마당이 자동으로 되는 편의"에 돈을 낸다).

- **유료 $2~4**: Wallpaper Engine 모델. $100을 회수하려면 30~50개는 팔려야 한다
- **무료**: 다운로드는 훨씬 많이 나오지만 $100은 못 돌려받는다. 창작마당 생태계는 더 빨리 큰다

> 참고로 **무료로 내도 $100은 내야 한다.** 회수 조건(매출 $1,000)은 무료 앱이면 성립하지 않는다.

### 이름
스토어에서 "Rubber Duck Debugger"로 검색 충돌이 없는지 확인이 필요하다.

## 5. 자주 걸리는 함정

- **30일 대기를 모르고 출시일부터 잡는 것.** 결제 시점 기준이다
- **`steam_appid.txt` 를 배포 빌드에 넣는 것.** 개발용 파일이다
- **창작마당 아이템에 미리보기 이미지 누락.** 목록에서 회색 네모로 뜬다 (업로드 시 필수 처리해 둘 것)
- **세금 서류 누락.** 30% 원천징수로 떼인다
- **스팀 오버레이.** Electron 앱은 오버레이가 안 뜨는 게 정상이다. 문제는 아니지만 사용자 문의가 올 수 있다
